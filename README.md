# 🛒 نظام كاشير وإدارة المبيعات (Cashier POS System)

نظام متكامل واحترافي لإدارة المبيعات، المخازن، المطاعم (نظام الطاولات)، وشؤون الموظفين. تم بناء هذا النظام ليقدم تجربة مستخدم سريعة، مرنة، وسهلة الاستخدام عبر ربط واجهة أمامية قوية مبنية بـ **Flutter** مع خادم خلفي متين مبني بـ **Python Flask**.

---

## ✨ المزايا الرئيسية للتطبيق

### 1️⃣ نظام نقطة البيع (POS) المتقدم
- **سلة مشتريات ديناميكية:** واجهة سلة مرنة توضح المبلغ، مجموع الخصم، والسعر النهائي للطلب.
- **خصومات مخصصة:** إمكانية إضافة خصم مخصص لكل قطعة (خصم القطعة)، أو خصم على كامل كمية المنتج (الخصم الكلي)، وتعديل السعر النهائي بشكل مباشر ليتم حساب الخصم المتبقي ديناميكياً.
- **دعم الباركود والبحث الفوري:** إضافة المنتجات من خلال مسح الباركود، أو استخدام شريط البحث الفوري للبحث عن طريق الاسم أو التصنيف.
- **التوافق مع الأوزان والقطع:** دعم بيع المنتجات بالقطعة أو بالوزن (غرام، كيلو).

### 2️⃣ إدارة الطاولات (للمطاعم والمقاهي)
- نظام كامل لإضافة وإدارة الطاولات.
- تحويل الطاولة إلى حالة "مشغولة" وتخزين الطلبات الخاصة بها حتى يتم دفع الحساب.
- حساب الفواتير الخاصة بكل طاولة بشكل منفصل والتوافق التام مع نظام السلة.

### 3️⃣ إدارة المخزون والمنتجات
- **إضافة وتعديل المنتجات:** رفع صورة المنتج، توليد باركود، تحديد سعر الشراء، سعر البيع، والكمية الأولية.
- **توريد المنتجات وتتبع السجل (Restock):** إضافة كميات جديدة وتوثيق عمليات التوريد في "سجل التوريد" للمنتج.
- **تنبيهات المخزون:** تمييز المنتجات التي قارب مخزونها على النفاذ بلون مختلف في بطاقة المنتج.

### 4️⃣ التحليلات والإحصائيات (Dashboard)
- لوحة تحكم تعرض الأرباح، المبيعات اليومية والشهرية.
- إحصائيات للمنتجات الأكثر مبيعاً لمتابعة حركة السوق داخل متجرك.

### 5️⃣ إدارة الموظفين والصلاحيات
- نظام إدارة شامل للموظفين (كاشير، مدير، مشرف).
- **صلاحيات مخصصة:** إمكانية إخفاء سعر الشراء والأرباح عن الكاشير العادي، بالإضافة إلى منع تعديل المنتجات وحذفها.
- متابعة الورديات (Shifts) وحساب الأرباح في كل وردية.

### 6️⃣ إدارة المصروفات (Expenses)
- تسجيل المصروفات اليومية (كهرباء، أجور عمال، إيجار، وغيرها).
- استقطاع المصروفات عند حساب صافي الأرباح.

### 7️⃣ مرونة في قواعد البيانات
- يدعم التبديل السلس والتلقائي بين **SQLite** (للاستخدام المحلي البسيط) و **MySQL** (للشبكات والاستخدام المكثف).
- التبديل يتم عبر ملف `.env` أو مباشرة من خلال شاشة الإعدادات في التطبيق.

---

## 💻 التقنيات المستخدمة

- **الواجهة الأمامية (Frontend):** Flutter (يدعم Web, Windows, Android, iOS).
- **السيرفر (Backend):** Python Flask & RESTful APIs.
- **قواعد البيانات (Database):** SQLAlchemy ORM (يدعم SQLite و MySQL).

---

## ⚙️ طريقة التشغيل

### 1️⃣ تشغيل سيرفر الباك إند (Backend)
الخطوات:
```bash
cd backend
python app.py
```
> سيتم تشغيل السيرفر على الرابط: `http://127.0.0.1:5000`

قبل التشغيل الأول أو بعد تحديث متطلبات السيرفر: `python -m pip install -r requirements.txt`.

### 2️⃣ تشغيل تطبيق الفلاتر (Frontend)
الخطوات:
```bash
cd frontend
flutter run -d chrome --web-port=51168 --no-web-resources-cdn
# أو لتشغيله كتطبيق Windows مباشر:
# flutter run -d windows
```

## 🗄️ ضبط قاعدة البيانات (MySQL / SQLite)

يمكنك تحديد قاعدة البيانات في ملف `backend/.env` كما يلي:

- **للاستخدام المعياري (SQLite):**
  ```env
  DATABASE_TYPE=sqlite
  SQLITE_DB_PATH=app_database.db
  ```
- **للاتصال بقاعدة MySQL:**
  ```env
  DATABASE_TYPE=mysql
  MYSQL_USER=root
  MYSQL_PASSWORD=your_password
  MYSQL_HOST=localhost
  MYSQL_PORT=3306
  MYSQL_DB=my_flask_db
  ```

## تحديث التقارير والموارد البشرية

- التقارير تدعم الفترات المعتادة، آخر 1 أو 4 أو 6 أو 8 أو 12 أو 16 ساعة، وعدد ساعات مخصص، ومن تاريخ ووقت إلى تاريخ ووقت. البداية مشمولة والنهاية غير مشمولة؛ الأوقات حسب المنطقة الزمنية للجهاز.
- زر التنزيل يصدّر PDF عربي أو Excel أو CSV أو JSON للتقرير المفلتر، وللطلب الواحد، وللسلة كمسودة غير مدفوعة. تصدير السلة لا يسجل بيعاً ولا يخصم مخزوناً. تنزيل الملفات متاح في نسخة المتصفح الحالية؛ دعم التنزيل الأصلي للمنصات الأخرى مؤجل لمرحلة إصدارها.
- تصدير التقرير يستخدم نفس حدود الفترة المعروضة. صلاحيات الطلبات والكلفة والأرباح تُفرض في السيرفر أيضاً؛ الكاشير يصدّر طلباته فقط دون الكلفة والأرباح.
- كلفة البضاعة المباعة تُخصم مرة واحدة عند حساب الربح. التوريد منفصل عن المصاريف التشغيلية، ويظهر مع المصاريف في مجموع التدفقات الخارجة. قيود توريد المنتجات الوزنية القديمة لا تُعدّل تلقائياً وتحتاج مراجعة إذا كانت قيمتها مسجلة بالوحدة الخطأ.
- المالك والمطور يديران بيانات الموظفين وعقودهم وحضورهم ورواتبهم. إدارة حسابات الدخول منفصلة وتحتفظ بهرم الصلاحيات. اربط الموظف بحساب دخوله حتى يرى عقده من زر «عقدي وشروط العمل»؛ كل مستخدم يرى عقده وحده.
- العقد يحدد الأجر الشهري أو اليومي أو بالساعة، الدوام وأيامه، السماح بالتأخير، الخصومات والمكافآت وشروط العقد. العقود مؤرخة بالشهر؛ الدوام المدعوم حالياً يبدأ وينتهي في اليوم نفسه. الراتب الشهري لا يُجزّأ تلقائياً حسب تاريخ التعيين.
- الأيام غير المسجلة لا تعتبر غياباً تلقائياً. تُحسب قواعد العقد على سجلات الحضور، وتُراجع مسودة الراتب قبل الصرف. صرف الراتب يسجل مصروفاً مرة واحدة ويقفل الفترة المدفوعة؛ تغيير العقد أو الحضور بعد إعداد المسودة يستلزم تحديثها قبل الدفع.
- الإيجارات والاشتراكات والمدفوعات الشهرية تُدار كالتزامات متكررة، وتدخل المصاريف عند تأكيد الدفع؛ لا تُسجل تلقائياً كمصاريف لمجرد حلول الشهر.
- كمية المخزون متاحة للمنتجات الوزنية بالغرام. لا يمكن إكمال بيع يتجاوز المخزون، حتى لو أُرسل الطلب مباشرة إلى السيرفر.

بعد تحديث هذه النسخة، أعد تشغيل السيرفر ثم أعد تشغيل Flutter بالكامل (`R`) لتحميل التغييرات. التشغيل المحلي يستخدم الخطوط ومحرك الرسم المحفوظين محلياً بعد تثبيت المتطلبات أول مرة.
