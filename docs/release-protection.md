# حماية نسخ ويندوز المصدرة

التصدير يستخدم Cython لتحويل جميع وحدات خادم الكاشير ومفتاح التحقق العام إلى مكتبات .pyd، ثم PyInstaller لتغليف الخادم وInno Setup لإنشاء التنصيب. لا يتم توزيع مصادر Python الخاصة بالخادم أو ملفات C أو رموز التصحيح. مشغّل بدء البرنامج ومكتبات الطرف الثالث تبقى ضمن التغليف المعتاد؛ فحص الرخصة والحسابات والمبيعات داخل المكتبات المترجمة.

واجهة Flutter تُبنى Release مع --obfuscate و--split-debug-info. رموز التصحيح تُحفظ عند المجهز داخل release-build/symbols ولا تدخل حزمة الزبون. احتفظ بنسخة احتياطية منها لتشخيص أعطال كل إصدار.

يلزم تثبيت اعتماديات packaging/requirements-build.txt وأدوات Visual Studio C++ على جهاز الأدمن. أداة packaging/build_native.py تبني الواجهة وتكتب بصمة مخرجها؛ التصدير يرفض واجهة لا تطابق بناء التعمية، ويترجم الخادم لكل نسخة، ثم يفحص أرشيف البرنامج ويرفض وجود وحدات الخادم كـPython bytecode بدلاً من .pyd. تقرير الفحص في مجلد بناء النسخة باسم protection-report.json. لا يرجع إلى التصدير القديم إذا فشل البناء.

هذه حماية للكود من الاستخراج المباشر وتسهيل الهندسة العكسية، وليست ضماناً باستحالة التحليل أو التعديل. الموارد المرئية والخطوط وقاعدة SQLite وملفات الترخيص ليست مشفرة بهذه الخطوة. الترخيص موقّع ومربوط بالجهاز؛ مفتاح التوقيع الخاص يبقى عند الأدمن، ولا تتغير بيانات الزبائن الموجودة. النسخ القديمة تحتاج إعادة تصدير لتأخذ الحماية الجديدة.

مراجع: https://docs.flutter.dev/deployment/obfuscate و https://docs.cython.org/en/latest/src/userguide/source_files_and_compilation.html
